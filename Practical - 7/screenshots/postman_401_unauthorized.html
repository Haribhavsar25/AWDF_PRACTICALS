Postman • Authentication & Validation Middleware Failure Scenarios ITUE301 Practical 7
SCENARIO 1: Protected Route Without Token 401 Unauthorized
GET http://localhost:5000/tasks (No Authorization Header)
{
  "success": false,
  "error": "Access denied. No token provided. Authorization header must follow: Bearer <token>"
}

SCENARIO 2: Malformed or Expired Token 401 Unauthorized
GET http://localhost:5000/tasks (Header: Bearer invalid_token)
{
  "success": false,
  "error": "Authentication failed. Invalid or malformed token."
}
SCENARIO 3: Server-side Input Validation Failure 400 Bad Request
POST http://localhost:5000/tasks (Payload: {"title": "", "priority": "urgent"})
{
  "success": false,
  "error": "Input validation failed",
  "validationErrors": [
    "Task title is required and cannot be empty",
    "Invalid priority 'urgent'. Allowed values are: low, medium, high"
  ]
}
Architectural Benefit:
Request rejected at the middleware boundary before executing any database queries or touching MongoDB resources.
